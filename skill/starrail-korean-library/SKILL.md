# 스타레일 한국어 자료집

목표는 게임의 한국어 원문을 읽을 수 있는 자료집으로 만들고, 빠진 연결과 확인된 연결을 구분하는 것이다. 원문을 번역·창작해서 대체하지 않는다. 설정 해설은 별도 편집자 글로 표시하고 원문에 근거를 연결한다. 게임 파일은 읽기 전용으로 취급한다. 현재 내장 스키마는 4.5 클라이언트의 DesignV v4에서 관찰·검증한 구조다.

## 먼저 확인

1. 사용자가 지정한 `StarRail_Data`, 산출물 폴더, 기존 자료집·보고서를 확인한다. 진단·설명만 요청했으면 새 파일을 만들지 않는다.
2. 원본 폴더 밖에 새 산출물 폴더를 정한다. 기존 결과를 덮어쓰지 않는다. 추출 스크립트는 파일이 들어 있는 폴더를 거부한다.
3. 기존 공개 구조 스냅샷을 재사용한다. 필요하다면 [TurnBasedGameData](https://github.com/DimbreathBot/TurnBasedGameData)의 `Story`, `Config/Level/Mission`, `ExcelOutput` JSON만 별도 작업 폴더에 받는다. 커밋을 기록한다. 공개 TextMap을 로컬 원문의 대체 자료로 쓰지 않는다. 저장소의 코드·실행 파일은 실행하지 않는다.
4. 사용할 Python과 Git은 이미 설치된 런타임을 확인한다. 이 스킬의 Python 코드는 표준 라이브러리만 사용한다. 패키지·전역 설정을 추가할 필요가 없다.

## 실행

아래 경로는 변수다. 실제 확인한 경로로 바꾼다. Windows에서는 UTF-8 모드로 실행한다.

```powershell
python -X utf8 "<skill>/scripts/check_scenes.py" --game-data "<StarRail_Data>" --structure "<JSON snapshot>" --output "<new scene-checks.json>"
python -X utf8 "<skill>/scripts/export_library.py" --game-data "<StarRail_Data>" --structure "<JSON snapshot>" --scene-checks "<scene-checks.json>" --output "<new library directory>"
python -X utf8 "<skill>/scripts/verify_library.py" --output "<library directory>"
```

장면 검사는 선택 단계다. 생략하면 모든 보조 장면 연결을 미검증으로 표시한다. 대사 ID가 같은 상대 순서로 하나의 로컬 엔트리에 나타나는 장면만 `LOCAL_ID_ORDER_MATCH`로 표시한다. 이것은 바이트 발생 순서의 근거이며 로컬 제어 흐름·플레이 조건의 복원 성공이 아니다.

압축이 필요하면 검증과 화면 점검이 끝난 폴더만 ZIP으로 묶는다. 게임 원본이나 구조 스냅샷을 함께 넣지 않는다. 패키지 스크립트는 검증 통과를 확인하고 압축 내부 모든 파일을 대조한다.

```powershell
python -X utf8 "<skill>/scripts/package_library.py" --output "<library directory>" --zip "<new archive.zip>"
```

## 정리 원칙

- `시작.html`: 제목·자료 ID, 세계, 임무 종류, 자료 분류로 찾는다. 본문 검색과 전체 한국어 문자열 검색은 색인을 필요할 때만 읽는다. 폴더 전체가 있으면 파일을 직접 열어도 사용할 수 있도록 fetch 없이 만든다.
- 임무 → 장면 → 화자·대사·선택지로 읽는다. 선택지 이동 ID와 JSON 포인터, 원문 해시, 보조 장면 경로를 함께 보존한다. 정적 장면 목록을 하나의 플레이 순서로 합치지 않는다.
- 서적은 시리즈·권 내부 순번으로 정리한다. 캐릭터는 캐릭터·이야기 번호, 설정은 에이언즈·세계관·광추·유물·아이템·시뮬레이션 우주로 나눈다.
- 메시지는 시작 항목·다음 항목 ID를 보존한다. 관찰 스키마에서 Sender 1=NPC, 2=Player, 3=PlayerAuto, 4=System이다. NPC는 개별 ContactsID를 우선하고 없으면 그룹 연락처를 쓴다. 플레이어 변수는 그대로 둔다.
- 미귀속 대사는 ID순 별도 문서로 모두 보존한다. 미번역·누락은 명시하고 외부 본문이나 추측으로 채우지 않는다.
- 읽기 화면에서 줄바꿈·일부 서식 태그만 정리한다. 원문 CSV와 로컬 표 JSON은 원문·오프셋을 그대로 보존한다. 64비트 해시는 브라우저 데이터에서 문자열로 유지한다.
- 원본 파일 SHA-256, 표 엔트리·오프셋, 스키마 해시, 보조 구조 커밋·파일 해시를 보고서에 넣는다. 정확한 수록 수는 해당 실행 결과에서 읽는다.

## 문맥·설정집·검색 사이트

원문 보존용 추출물과 독서용 사이트를 구분한다. 읽기 화면 재구성, 설정 해석, Starlight·검색·게시 요청에서는 [references/contextual-site.md](references/contextual-site.md)를 읽는다. `assets/reading-site`는 실행 검증한 사이트 템플릿이며, 원문 데이터와 설치된 의존성은 포함하지 않는다.

- 내부 장면명은 접힌 출처에 보존한다. 표제는 화자·발화 또는 확인한 임무 목표로 표현한다.
- 로컬 MainMissionPack에서 같은 제목·종류·세계·챕터의 진행 조각만 통합한다. 세계 → 챕터 → 챕터 안의 진행 참조로 묶는다. 숫자 ID를 실제 플레이 순서라고 주장하지 않는다.
- 목표·설명은 로컬 SubMission에서 읽고, 선행 조건은 MissionInfo 구조와 함께 확인한다. 컷신의 선택지만 있는 경우 맥락과 누락 범위를 표시한다. 예시의 편집자 배치를 일반 연결 규칙으로 확대하지 않는다.
- 버전 탐색은 고정된 버전별 표의 최초 등장으로 구분하고, 출시 시점과 미확인 범위를 명시한다. 초기 버전은 임무 ID로 추측하지 않는다.
- 설정은 독자가 묻고 싶은 질문에서 시작한다. 서술자의 관점·시점·추측과 확정 사실을 구분하고, 비교할 기록 → 관계 → 해석 → 인용 원문 → 추천 읽기 순서를 만든다. 키워드 동시 등장만으로 인과나 동일성을 확정하지 않는다.
- 사이트 게시가 요청되었을 때만 대상 저장소에 게시한다. 공개본에는 게임 바이너리·인증 자료·개인 절대 경로·작업용 전체 원문 CSV를 넣지 않는다. 현재 저장소 HEAD와 배포 결과를 확인한다.

## 검증과 완료

1. 카탈로그 엔트리·표·한국어 TextMap의 길이·행 수·EOF가 일치해야 한다. 알 수 없는 활성 필드, 다른 헤더, 누락 파일은 중단한다. 억지로 부분 디코딩하지 않는다.
2. 검증기는 원본을 다시 읽어 원문 CSV·표를 대조하고, 본문·화자 해시와 메시지 발신자·분기를 확인한다. 모든 로컬 대사 ID, 서적 본문, 캐릭터 이야기의 보존과 HTML·TXT·CSV·검색 색인 일치를 검사한다.
3. 브라우저에서 제목 검색, 본문 검색, 원문 검색, 서적 읽기, 임무의 선택지, 메시지 화자를 확인한다. 모바일 사용을 요청받으면 작은 화면의 분류 선택과 읽기 폭도 확인한다. 검증 통과만으로 실제 플레이 순서의 정확성을 주장하지 않는다. 앱 브라우저가 로컬 파일 주소를 차단하면 우회하지 않고, 생성한 자료집 폴더만 제공하는 localhost에서 확인하며 직접 파일 열기는 미검증으로 기록한다.
4. 링크로 자료집·원문·검증 결과를 전달하고, 사용자는 `$starrail-korean-library`로 다음 추출을 요청할 수 있다고 알려준다. 공개 업로드는 별도 요청 범위다.

세부 형식·확인된 한계는 [references/format-and-evidence.md](references/format-and-evidence.md)를 읽는다. `assets/schemas-v4.json`은 원문이 없는 필드 배치이며 버전 변화 시 검증 근거 없이 자동 수정하지 않는다.
